# SessionLender для Windows — кастомні сповіщення

Go-додаток із власним вікном SessionLender, треєм і фоновим WebSocket. Основний інтерфейс використовує встановлений системний Microsoft WebView2. Сповіщення — окремі нативні Win32-вікна, без стандартного центру сповіщень Windows.

## Запуск

1. Оновіть сервер за `server/README.md` із сусідньої папки архіву.
2. Замініть старий EXE новим, повністю завершивши попередній через меню трея.
3. Запустіть `SessionLender.exe`, увійдіть.
4. Права кнопка на значку трея → «Перевірити власне сповіщення». Цей тест працює без другого акаунта й без серверного підключення.

Потрібні Windows 10/11 x64 та Microsoft Edge WebView2 Runtime. Офіційне завантаження: https://developer.microsoft.com/microsoft-edge/webview2/

Хрестик головного вікна залишає програму в треї. Подвійне натискання на іконку повертає вікно. «Вийти» завершує отримання подій. Автозапуск і збереження вимкненого стану сповіщень між запусками поки не реалізовано.

## Вигляд і взаємодії

- Безрамкове вікно справа внизу монітора головного вікна, поверх інших вікон, без перехоплення фокуса клавіатури.
- Суцільна затемнена скляна картка з тонким світлим краєм і плавними прозорими кутами. Зліва аватар із заокругленням, праворуч нік і текст; оформлення наближене до компактного вікна плеєра.
- Системний blur за доступності та прозорий растровий шар усієї картки. Ефект залежить від версії Windows і дозволеної прозорості; на непідтримуваній конфігурації залишається темне оформлення.
- Унизу кнопок немає. Значок квадрата зі стрілкою вгорі відкриває подію в головному додатку; × закриває картку.
- Натискання сповіщення про повідомлення відкриває окремий компактний чат 440 × 440 з історією та полем надсилання. Це поточний вебчат зі спільною авторизацією WebView2, без повторного входу. Для інших подій відкривається головний додаток.
- Компактний чат не закривається за таймером. Його можна пересунути за заголовок, закрити хрестиком або відкрити у головному додатку значком зі стрілкою.
- Надісланий користувачем MP3 вбудовано в EXE. Він відтворюється асинхронно через Windows MCI при появі картки; швидка серія сповіщень перезапускає один звук. Звук не програється для прихованих сповіщень активного чату.
- Автоприховування через 9 секунд. Під курсором таймер призупиняється; після відведення лишається ще 3 секунди.
- До трьох карток одночасно, до 30 очікують у черзі. При зміні акаунта картки очищуються.
- Аватар завантажується окремо, без затримки появи картки; поки його немає, видно логотип. Підтримуються PNG/JPEG/GIF/WebP до 2 МБ і 4 млн пікселів.

Нові картки не зберігаються в центрі сповіщень Windows. На заблокованому/захищеному екрані власне вікно не показується. Повний журнал подій залишається на сайті, відповідно до наявної серверної логіки.

## Отримання подій

Після завантаження авторизованої сторінки захищений CSRF POST `/desktop/session/` видає випадковий ключ із терміном дії одна година. Ключ потрібний тільки для inbox WebSocket та читання аватарів. Пароль і HttpOnly cookie не передаються в Go. Ключ оновлюється раз на 20 хвилин; тимчасові помилки повторюються через 2–60 секунд. Це обслуговування авторизації, не опитування повідомлень.

Go тримає окремий WebSocket `/ws/inbox/`, працюючи й при прихованому вікні. Повідомлення, дописи, коментарі, вподобання та події кімнат надходять із наявного серверного каналу. Є ping/pong та перепідключення. Наявний сервер при повторному вході віддає до 20 непрочитаних повідомлень; повний журнал пропущених інших подій не додається.

Історія останніх 500 ID для кожного акаунта запобігає повторам. У ній немає тексту повідомлень. Аватари з приватного маршруту отримуються за desktop-ключем; Authorization не передається зовнішньому Blob-хосту при перенаправленні. Дозволені лише HTTPS-адреси сервера й публічного Vercel Blob. Розмір і роздільність зображень обмежені.

## Код

- `cmd/sessionlender`: запуск одного екземпляра, журнал.
- `internal/config`: сервер, каталоги, перевірка внутрішніх URL.
- `internal/events`: WebSocket, авторизація, перепідключення, ID показаних подій.
- `internal/desktop/app_windows.go`: головне вікно та зв’язок компонентів.
- `native_windows.go`: трей, меню, базові Win32-функції.
- `notifications_windows.go`: створення карток, черга, таймери та кліки.
- `popup_render_windows.go`: прозорий Win32-шар, текстові маски й малювання.
- `glass_surface.go`: згладжені кути, напівпрозорий тон і тонкий край.
- `active_chat.go`: правило приховування лише для того самого активного чату.
- `avatar.go`, `popup_avatar_windows.go`: асинхронні аватари та безпечне декодування.
- `quick_chat_windows.go`: окремий UI-потік, COM, авторизоване вікно швидкої відповіді.
- `quick_chat.js`: компактний вигляд існуючого чату, кнопки й локальний стан фокуса.
- `notification_sound_windows.go`: асинхронне відтворення вбудованого MP3 через MCI.
- `bridge.js`: синхронізація поточного входу з Go.
- `vendor`: зафіксовані залежності з ліцензіями; локальні зміни в `VENDOR_CHANGES.md`.

Адреса зафіксована в `internal/config/config.go`: `https://sessionlender.vercel.app`. Дані в `%APPDATA%\SessionLender`: профіль WebView2, іконки, ID історії та `desktop.log`. Паролі, ключі та текст повідомлень у журнал не записуються. Старі COM-записи попередньої версії не використовуються.

## Збирання

Go 1.24+, без C/C++ компілятора, Node.js та Android Studio. Усі залежності є у vendor. Запустіть `build.cmd` — політика виконання PowerShell не впливає на цей спосіб. Результат: `build\SessionLender.exe`.

Або PowerShell-команди напряму з папки вихідного коду:

```powershell
$env:GOOS = 'windows'
$env:GOARCH = 'amd64'
$env:GOAMD64 = 'v1'
$env:CGO_ENABLED = '0'
New-Item -ItemType Directory -Force build | Out-Null
go build -buildvcs=false -mod=vendor -trimpath -ldflags '-s -w -H windowsgui' -o build\SessionLender.exe ./cmd/sessionlender
```

Не запускайте `go mod vendor` поверх підготовленої папки без збереження native origin-перевірок. Піктограма вже вбудована у `cmd/sessionlender/resource_windows_amd64.syso`.

## Перевірки

Go-тести: WebSocket, дублікати, URL, історія, обмін сесією під час очікування UI, аватари. Django: повний набір — 99 тестів, включно з реальним HTTP-надсиланням через авторизовані WebSocket і SSE. Перевірено синтаксис bridge.js та збирання Windows GUI x64. Для Win32 callback використовується нативний lParam/unsafe.Pointer; vet запускати з `-unsafeptr=false` на цьому інтеграційному шарі.

Кроскомпіляція виконана на Linux. Реальний вигляд DWM-скла, показ карток та взаємодії мишкою на Windows тут не перевірено. Збірка тестова й без цифрового підпису.

Якщо тестова картка з трея є, а повідомлень немає: перевірте статус заголовка, наявність `/desktop/session/`, застосування міграції `0007_desktop_ticket` та журнал `%APPDATA%\SessionLender\desktop.log`. Точну причину попередньої відсутності системних банерів без журналу не встановлено.

## Показ при відкритому додатку

Сповіщення приходить і при відкритому головному вікні. Воно приховується лише для повідомлення з того самого чату, якщо цей чат видимий, у фокусі й головне вікно є foreground-вікном Windows. Інший чат, стрічка, згорнуте чи неактивне вікно не блокують сповіщення. Стан сторінки передається локально в Go без HTTP-запитів, за подіями focus/blur/visibilitychange та коротким локальним heartbeat.

Якщо WebSocket не встановлюється, Go переходить на `/desktop/events/` — один відкритий потік SSE. Сервер сам передає події, опитування повідомлень немає. При обриві потік перепідключається. В заголовку видно, який канал підключений; журнал фіксує отриманий ID події без тексту.

Оновлення намальоване через UpdateLayeredWindow із правильним premultiplied alpha. GDI застосовується тільки для текстових масок; написи не повинні створювати окремі чорні прямокутники на склі. Фактичний вигляд на вашій Windows потребує перевірки — у середовищі збирання Windows немає.

## Поточне оновлення: швидка відповідь і звук

Серверні файли в цьому оновленні не змінювалися: якщо попередній патч уже встановлено, достатньо повністю вийти через трей і замінити EXE. Сповіщення приглушується для того самого видимого чату у фокусі як у головному вікні, так і у компактному. Компактне вікно не створює ще одного фонового inbox-підключення й не перевидає desktop-ключ. Для перевірки швидкої відповіді потрібне справжнє повідомлення з іншого акаунта; тестова картка трея веде на сторінку сповіщень.

Збирання, Go-тести та синтаксис обох JS-файлів перевірено. Роботу другого WebView2-вікна, MCI-звуку та фактичний вигляд на Windows потрібно перевірити на пристрої. Цифрового підпису немає.
